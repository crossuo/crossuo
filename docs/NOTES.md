# Implementation Notes

## T1 — Shard/link/product fields in g_Config (2026-10-04)
- New fields: `DataProductUrl`, `ShardWeb/Account/Help/Video/Credits/Discord` (white_label defaults; `ShardDiscord` default-empty). Keys: `producturl`, `shardweb`, `shardaccount`, `shardhelp`, `shardvideo`, `shardcredits`, `sharddiscord`.
- Save-back writes a field only when it differs from its white_label default (ShardDiscord: only when non-empty) so defaults never bake into crossuo.cfg and future shard switches aren't fought by stale values.
- Empty-value asymmetry (intentional): `TextFileParser` drops empty tokens, so `shardweb=` (size==1) clears the field via a pre-switch scoped to the 7 new keys; a bare key line with no `=` also clears (pre-existing keys keep defaults in that case). Left as-is: key present ⇒ value empty.
- Pre-existing, out of scope: `,` is a cfg value delimiter (string values truncate at first comma); save-key casing (`ProductUrl=`) differs from load keys (`producturl`) — matches `ShardName=` precedent, load is case-insensitive.

## Web streaming: real progress + cacheable responses (2026-10-06)
- Progress: byte counter at the http_xhr_get chokepoint (vfs_web_bytes_done/total/expect, EMSC-only, native no-op stubs); denominators = loose-tier planned bytes + stream-lane compressed_total on learn + punctual block sizes once per hash; vfs_boot_web_progress = done/max(total,done) clamped [0,0.99], 1.0 only at boot-done, keeps flowing post-boot (all 10 old writers deleted). Exported via -sEXPORTED_FUNCTIONS; shell.html polls (500ms) and renders "streaming X / Y MB (Z%)" in #status (?log=1) or a bottom-left overlay on the bare page (hidden when idle/complete).
- Cacheability: web http_get now does plain whole GET (200, cacheable) FIRST; probe+8MB-chunked assembly is only the fallback (transport error/timeout/non-200; cap excess = hard fail, no fallback). xuoproxy /patch/files 200s+206s: ETag + Cache-Control immutable + Accept-Ranges; manifests no-cache + ETag + If-None-Match→304; generic route forwards upstream ETag on byte-identical bodies; 206s still never cached.
- Proxy cache format v2: [status:2][ctype_len:4][etag_len:4][etag][ctype][body] — body-hash ETag stored at cache_put, windowed 206s serve the SAME validator (was cache-key ETag = split-brain); v1 entries deterministically rejected (quote guard) → miss → rewrite.
- Known follow-up: inherently-ranged punctual granule + stream-lane reads stay 206 (browser partial-cache is best-effort even with validators); the durable repeat-session fix is persisting the streamed install (IDBFS/OPFS) — reverses the "browser http cache keeps the blobs" design note, needs its own round. wasm-only pre-existing warning list unchanged (9): EM_JS shims, unused ret, loguru, ART_ARRAY_INITIAL_LAYERS, vfs_boot_web_mkdirs, empty char const, fs.h:963 return.

## Web overlay v2: shared-heap counters + throughput mode (2026-10-06)
- The first overlay polled Module._vfs_web_bytes_* from the PAGE — in PROXY_TO_PTHREAD builds exports bind on the worker, so the overlay never fired ("no progress bar at all"). Counters now form a contiguous 8-aligned struct in the shared wasm heap (vfs_web_progress_counters, http.cpp); the page polls its address via the exported _vfs_web_progress_addrs and reads HEAPU64[addr>>3]/[+1] directly (view re-fetched per poll for memory-growth safety; -sEXPORTED_RUNTIME_METHODS=HEAPU64 added; BigInt→Number).
- Overlay UX: percent mode while done ≤ registered total (bounded boot phase: "streaming 250/730 MB (34%)"), throughput mode once done exceeds it ("streamed 1.1 GB (12.4 MB/s)", open-ended sweep, no fake percent); visible while bytes move (2s rate window), hidden when idle/done==0. The old frac<0.99 hide degenerate-hid the bar when sweep bytes outgrew the ~90MB boot denominator.
- Expectation to set: 206s during granule/stream reads are by design (inherently ranged); whole-blob fetches are 200s. Durable repeat-session reuse = persist the streamed install (IDBFS/OPFS) — pending design decision.
- Live-verified headless (CDP, xuoproxy :8777, ?shard= deep link): boot → 8s initialization completed; overlay polled in-page showing real byte counters through the shared heap and throughput-mode text during the sweep.

## Progress counter fix: pointer-add bug (amended into 04c14df8b)
- `uint64_t(len)` added the body-buffer ADDRESS instead of `*len` — the counter accumulated malloc addresses (1.2 GB early, tens of GB as the heap grew; identical "sizes" across packs = reused heap addresses; a session with ZERO wire traffic still read 1.17 GB). Fixed to `*len`; ranged 200 bodies (rejected by the caller) uncounted; session dedupe per (url|range) so browser-cache re-serves/retries count once, matching the once-per-target denominator. Post-fix: done ≈ wire bytes (121.9 vs 121.63 MB measured). Throughput display shows rate + session delta, not the lifetime counter.
- xuoproxy: manifest link rewriter generalized from the hardcoded 250 patch-repo version to any version segment (upstream moved to 251; absolute CDN urls were CORS-blocked, killing granule fetches).

## Phase 0 freshness: web updates propagate (2026-10-06)
- xuoproxy was a snapshot: cache TTL 0 + no purge + no upstream revalidation froze the product at first fetch — including manifests (disk hit short-circuited upstream), so web clients certified a stale snapshot forever (browser no-cache+ETag revalidated against the proxy's own stale body: 304s that meant nothing).
- Phase 0 (main.rs only, client untouched): manifests revalidate upstream per request (conditional GET with stored ETag/Last-Modified; --manifest-ttl throttles; upstream errors serve stale); cache entry v3 adds a metadata trailer (upstream validators + referenced-url set); on changed manifest bodies the OLD referenced content entries are invalidated; rewrite_links stamps every rewritten resource url with ?v=<per-entry token (mft t= attr / ul+cl hash) else manifest validator> — changed entries get new tokens (browser fetches fresh), unchanged entries keep tokens (browser cache stays valid). strip_version_param removes ?v= before cache-key/upstream derivation on EVERY incoming reference (files/generic/stream/blob u=) — the linchpin.
- Aops lane mapped + covered: patchlist/patchcfg/data files all flow through /stream + /patch/eamythic; patchlist change → invalidation of per-relpath data entries (parse ported from client: UTF-16 pipe-list, online_patch_directory + custom_extension from patchcfg).
- Verified: curl matrix (revalidation, 304, targeted invalidation, ttl throttle) + headless E2E gold proof: aops mirror boot → initialization completed; upstream content+stamp change with NO cache clearing → next boot materialized the new bytes (VERSION-2-PAYLOAD via MEMFS) → initialization completed; control boot = 304 + cached serve. Native-style plan serial drift lines are native-only (web has no persisted plan.bin — IDBFS whitelist excludes /install; vfs.cpp:3221 comment is stale).
- Remaining 10%: same-size same-metadata in-place edits stay invisible (token derives from manifest entry attrs) — accepted; options later: deep-verify sampling or content-hash chunk index (CAS).

## Web client statefulness: persisted appdata root (2026-10-04)
- Problem: the page's MEMFS dies with the session and the shell's idbfs whitelist never matched where the client actually writes. On web `fs_path_appdata()` resolved to an EMPTY path (emcc defines none of `__linux__/__APPLE__/_WIN32` in this toolchain, so every branch skipped), making `FilePath()` cwd-relative (`/crossuo/...` at the fs root) — the shell's `/desktop` whitelist entry was dead (client wrote `/crossuo/desktop`), and only the ExeFilePath-rooted files (`/crossuo.cfg`, `/crossuo.log`, `/xuoassist.ini`) persisted.
- Fix (common/fs.h): `__EMSCRIPTEN__` branch first in `fs_path_appdata()` returns `/data` — the shell's idbfs mount point. Everything client-generated composes under it: `FilePath()` → `/data/crossuo/...` (desktop profile saves, FilePath crossuo.cfg fallback, world-map cache), assistant root `GetRootPath()` → `/data/crossuo/{Config,GlobalConfig}/...` (all ~20 ini files). Native paths byte-identical (branch is wasm-only).
- Install relocation (src/Main.cpp load_config): now unconditional for the derived dir (not just non-absolute paths) — with appdata=/data, `FilePath(shard)` became absolute and would have landed the streamed install inside the persisted tree. Explicit `--streaming` CLI dirs keep their absolute meaning.
- shell.html whitelist: trees `['/data/crossuo', '/screenshots']` (screenshots are ExeFilePath-rooted user data), files unchanged, per-file cap 1MB→8MB (custom houses can exceed 1MB), tree depth 6. Persist tick now also stores DIRECTORY entries: the idbfs restore path (`libidbfs.js`) writes entries in ascending path order and `mkdirTree`s dirs before files, so nested profile dirs are recreated on restore. Best-effort flush added on `pagehide` + `visibilitychange(hidden)`; the 30s tick remains the durability contract (idbfs writes are async — a pagehide flush usually commits but is not guaranteed). Legacy `/desktop` whitelist entry removed (it never matched a real path; nothing was persisted there).
- Write-site enumeration (web paths after the fix; all persisted unless noted): SaveGlobalConfig `GetConfigFile()` → `/crossuo.cfg` (existing file wins; else `/data/crossuo/crossuo.cfg`); SaveLocalConfig options/skills/macros/gumps/customhouses + `<serial>_<char>.xuo` → `/data/crossuo/desktop/<acct>/<server>/0x…/`; ConfigManager options.cfg + player .xuo writes same root; assistant ini (Profiles/Options/Types/FindList/IgnoreList/SpeechFilter/TextReplaces/SoundFilter/ShopList/DisplayItems/DisplayGroups/Map/Objects/Hotkeys/Party/Friends/Enemies/Macros…) → `/data/crossuo/{GlobalConfig,Config}/…`; GumpWorldMap cache → `/data/crossuo/data/`; screenshots → `/screenshots/` (format-dependent, >8MB files are skipped by the cap); loguru → `/crossuo.log`. NOT persisted by design: `/install/<shard>/…` streamed install + vfs blob cache (re-fetchable, session-local); `UOFilePath` reads only — `autologinnames.cfg` and `Prof.txt` are install data the client never WRITES (the only writer is the out-of-scope tools/xuoi installer); animation/uop dumps are debug-flag-only.
- localStorage rejected per requirements (sync API, ~5MB quota, no file semantics — can't back a POSIX path tree); idbfs+IndexedDB works on Chrome/Firefox.
